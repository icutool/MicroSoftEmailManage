# 开发-邮件页标签包含与排除筛选

## 需求

邮件查看页（"选择邮箱"面板）原本只能"只展示某个标签"的账号，需要：

1. 同时支持"包含标签"和"排除标签"两种筛选条件，并且两者可以叠加生效（多选）。
2. 调整布局：搜索框单独一行，包含筛选和排除筛选占同一行。

## 最终交互设计

```
[ 搜索邮箱                          ]   <- 单独一行
[ 包含标签 ▾ ]  [ 排除标签 ▾ ]          <- 包含 / 排除同一行
当前显示 12 / 总计 40 个邮箱  [包含：A] [排除：B]
```

- 两个下拉都是多选面板（勾选框），可同时勾选多个标签。
- 同一个标签不能既包含又排除：在一边勾选后，另一边同名标签会自动取消勾选并被禁用。
- 触发按钮上直接显示已选标签（超出宽度用省略号），按钮边框高亮表示该筛选生效中。
- 统计文案后面追加当前生效的"包含 / 排除"标签小标签，避免误判筛选结果。
- 点击按钮外部或按 `Esc` 关闭下拉面板。

## 筛选语义

`static/app.js` 中的 `matchesMailTagFilters(account, includeTags, excludeTags)`：

- **排除优先**：账号只要命中任意一个排除标签，就直接被过滤掉。
- **包含为"或"关系**：勾选了包含标签时，账号命中其中任意一个即可保留；未勾选包含条件时不限制。
- **"无标签"选项**：
  - 包含里勾选"无标签" = 只看没有任何标签的账号；
  - 排除里勾选"无标签" = 过滤掉所有带标签的账号（即只看无标签账号的补集）。
- 邮箱关键字搜索与标签筛选是"与"的关系，同时生效。

## 变更文件

### `templates/index.html`

- 搜索框 `#mail-search-input` 从筛选行里提出来，单独占一行。
- 新增 `.filter-row.filter-row-tag-filters`，内部是两个 `.tag-filter` 下拉组件：
  - 包含：`#mail-tag-include-trigger` / `#mail-tag-include-panel` / `#mail-tag-include-options` / `#mail-tag-include-clear`
  - 排除：`#mail-tag-exclude-trigger` / `#mail-tag-exclude-panel` / `#mail-tag-exclude-options` / `#mail-tag-exclude-clear`
- 原来的 `#mail-tag-filter`（单选下拉）和 `#mail-tag-filter-mode`（模式下拉）已移除。

### `static/app.css`

- 新增 `.filter-row-tag-filters`：两列等宽，让包含 / 排除并排一行（窄屏 ≤980px 时沿用已有的 `.filter-row { grid-template-columns: 1fr; }` 自动堆叠为两行）。
- 新增下拉组件样式：`.tag-filter` / `.tag-filter-trigger` / `.tag-filter-panel` / `.tag-filter-options` / `.tag-filter-option` / `.tag-filter-clear` / `.tag-filter-caret`。
- 新增统计小标签样式：`.filter-chip` / `.filter-chip-include` / `.filter-chip-exclude`。
- 面板高度限制为 `min(240px, 40vh)`：因为外层 `.panel` 是 `overflow: hidden`，避免下拉被裁切。

### `static/app.js`

- 常量：新增 `TAG_FILTER_INCLUDE` / `TAG_FILTER_EXCLUDE` / `TAG_FILTER_MODES`；移除上一版临时的 `TAG_FILTER_MODE_*`。
- `state.mailTagFilter = { include: Set, exclude: Set }`：邮件页的筛选条件，两个集合同时参与过滤。
- 新增 `tagFilterUi`：包含 / 排除两套下拉的 DOM 引用。
- `updateTagFilterOptions()`：账号管理页仍保持原来的单选"包含"下拉；邮件页改为重建两个多选面板，并清理已被删除的标签勾选（`pruneMailTagFilter`）。
- 新增函数：`renderTagFilterOptions`、`syncTagFilterOptionState`、`toggleMailTagFilter`、`clearMailTagFilter`、`formatTagFilterTriggerLabel`、`updateTagFilterTriggerLabels`、`setTagFilterPanelOpen`、`closeTagFilterPanels`、`getOppositeTagFilterMode`、`matchesMailTagFilters`、`getMailFilteredAccounts`、`renderMailFilterSummary`。
- `renderAccounts()` 改用 `getMailFilteredAccounts()`，统计文案改用 `renderMailFilterSummary()` 渲染（带包含 / 排除小标签）。
- 事件绑定：两个触发按钮的展开 / 收起、两个"清空"按钮、`document` 点击外部关闭、`Esc` 关闭。

## 影响范围

- 仅影响邮件查看页的账号筛选。
- 账号管理页的 `#tag-filter`（单选包含筛选）和账号导出接口 `/api/accounts/export?tag=` 逻辑不变。
- 筛选仍在前端完成，未改动后端接口。

## 验证方式

1. 打开邮件查看页：搜索框单独一行，包含 / 排除两个下拉一行。
2. 包含下拉勾选标签 A：只显示含 A 的账号，按钮显示"包含：A"，统计后出现绿色小标签。
3. 排除下拉勾选标签 B：在只含 A 的结果里再过滤掉含 B 的账号，统计后出现橙色小标签。
4. 在包含里勾选 B：排除里的 B 自动取消并变为禁用状态（同一标签不能既包含又排除）。
5. 点"清空"：对应条件被清空，列表恢复。
6. 包含里勾选"无标签"：只显示没有任何标签的账号；排除里勾选"无标签"：只显示有标签的账号。
7. 点击面板外部或按 `Esc`：下拉关闭。
8. 窄屏（<980px）：包含 / 排除自动堆叠为两行，面板正常显示不被裁切。

> 注意：`templates/index.html` 里 `app.js` / `app.css` 没有版本号参数，浏览器可能命中缓存，验证前请强制刷新（Ctrl+F5）。
