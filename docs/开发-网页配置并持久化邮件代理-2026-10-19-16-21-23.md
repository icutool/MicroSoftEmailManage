# 网页配置并持久化邮件代理

## 需求

代理不再依赖启动时的环境变量，而是从网页配置、保存到 SQLite，并用于后续 OAuth 和 IMAP 请求。

## 已确认变更

- 新增 `app_setting` 表，使用 `mail_http_proxy` 保存代理地址。
- 使用 `mail_http_proxy_user` 保存可选的代理认证字符串，格式为 `用户名:密码`。
- 新增 `GET/PUT /api/settings/proxy` 接口，沿用后台 token 鉴权。
- 后台新增“系统设置”页面，可加载、保存代理地址和认证信息，或清空后恢复直连。
- 每次邮件请求从数据库读取最新代理，因此保存后无需重启服务即可生效。
- OAuth 使用数据库代理并关闭系统环境代理，认证信息通过 Requests 代理 URL 使用；IMAP SSL 使用 HTTP CONNECT 隧道，并在 CONNECT 请求中发送 Basic `Proxy-Authorization`。
- 支持 `http://127.0.0.1:7890` 形式，也支持带 URL 编码用户名密码的 HTTP 代理。
- 网页认证输入框使用密码类型隐藏内容；认证信息由受后台 token 保护的设置接口读取，数据库文件应按敏感数据妥善保管。

## 使用方式

登录后台后点击“系统设置”，填写：

```text
http://127.0.0.1:7890
```

若代理要求认证，在“代理认证”输入框填写：

```text
proxyuser:xtXT1234
```

点击“保存代理设置”即可启用；点击“清空并直连”会同时清除代理地址和认证信息。
