# 新增按邮箱地址取件接口

## 背景

后台页面取件一直使用数据库自增 ID：

```text
GET /api/accounts/96/mails?folder=inbox
GET /api/accounts/96/mails?folder=junk
```

这个 ID 是数据库内部主键，第三方调用方无法从邮箱地址直接推导，必须先查一次账号列表拿到 ID，再发起取件请求，调用链路长且容易因为账号重新导入而失效。

## 已确认的变更

- 新增按邮箱地址取件接口，第三方只需要邮箱地址即可取件，不再依赖自增 ID。
- 新接口支持 `folder=inbox`（收件箱）和 `folder=junk`（垃圾箱）两种取件场景。
- 新接口支持 `limit` 参数控制返回邮件数量，取值范围 `1~50`，默认 `20`。
- 新接口鉴权同时支持 `X-Token` 请求头和 `token` 查询参数，方便脚本、无代码平台、浏览器直接打开链接等不方便自定义请求头的调用方。
- 邮箱地址查找大小写不敏感，并自动去除首尾空格，避免第三方传入的大小写与导入时不一致导致查不到账号。
- 返回体在原有 `items` 基础上补充 `account_id`、`email`、`folder`、`count` 字段，便于调用方确认命中的账号和文件夹。
- 保留原有按 ID 取件接口 `/api/accounts/{account_id}/mails`，后台页面继续使用，已有第三方调用不受影响。
- 两个取件接口共用同一套取件逻辑（文件夹校验、耗时日志、错误转换），避免后续修改出现行为不一致。

## 接口说明

### 按邮箱地址取件（新增）

```text
GET /api/accounts/mails?email=demo@hotmail.com&folder=inbox
GET /api/accounts/mails?email=demo@hotmail.com&folder=junk
GET /api/accounts/mails?email=demo@hotmail.com&folder=inbox&limit=5
```

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `email` | 是 | 邮箱地址，例如 `demo@hotmail.com` |
| `folder` | 否 | `inbox` 收件箱（默认）、`junk` 垃圾箱，其他值返回 400 |
| `limit` | 否 | 返回邮件数量，`1~50`，默认 `20` |
| `token` | 否 | 后台密码，作为请求头 `X-Token` 的替代方式 |

请求示例：

```bash
curl "https://emaildash.icutool.cn/api/accounts/mails?email=demo@hotmail.com&folder=inbox&token=后台密码"
```

返回示例：

```json
{
  "account_id": 96,
  "email": "demo@hotmail.com",
  "folder": "inbox",
  "count": 2,
  "items": [
    {
      "id": "13",
      "subject": "邮件主题",
      "mail_from": "发件人",
      "mail_to": "收件人",
      "mail_dt": "2026-10-19 12:00:00",
      "body": "<html>...</html>"
    }
  ]
}
```

### 按 ID 取件（保留）

```text
GET /api/accounts/{account_id}/mails?folder=inbox
```

该接口仅支持 `X-Token` 请求头鉴权，返回体结构与新接口一致，后台页面继续使用。

## 错误码

| 状态码 | 场景 |
| --- | --- |
| `401` | 未携带正确令牌 |
| `404` | 邮箱地址在系统中不存在 |
| `400` | `folder` 不是 `inbox` / `junk`，或邮箱侧取件失败（令牌失效、IMAP 认证失败、网络超时等） |

## 验证

- 已使用 Python 3.12 执行 `compileall`，`icutool_mail.py`、`mail_service.py` 编译通过。
- 已本地启动服务实测：无令牌返回 `401`，未知邮箱返回 `404`，非法 `folder` 返回 `400`。
- 已实测 `folder=inbox` 与 `folder=junk` 均返回 `200` 并成功取到邮件（走 HTTP 代理链路）。
- 已实测按 ID 的老接口仍返回 `200`，行为未受影响。
